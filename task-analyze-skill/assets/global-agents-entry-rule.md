# Global Codex Task Entry Rule

Merge this section into `~/.codex/AGENTS.md`. This is a hookless workflow: do not install or require lifecycle hooks, and never print internal route JSON in chat.

For every new user-owned Codex task, start with the independent global skill `~/.codex/skills/task-analyze-skill/SKILL.md` before answering, editing, running a requested command, opening/controlling an app, or invoking another user/global skill.

- This is a 100% task-start contract covering direct answers, reads, status checks, commands, edits, code, prompts, visuals, documents, verification, optimization, management, and mixed work.
- The selected entry model and effort run Task Analyze and route coordination only. In bounded read-only preflight call `task-analyze-skill/scripts/resolve_entry_model.py`; preserve its exact verified pair and use `unverified` only when resolution fails. Never treat the entry pair as the workflow-wide model or a fixed default.
- Before the visible route, perform only the smallest read-only preflight needed to classify the task. Read Task Analyze completely, then batch `python3 resolve_entry_model.py` and at most one memory-bridge query in the first tool round. Do not load Workflow, the downstream owner, Verify, or code-language rules in the entry; each bounded downstream node reads its own owner. This entry is exempt from full Obsidian/project-memory bootstrap: never walk vault indexes or load whole project/daily/aesthetic pages there. Inject only necessary context and defer full memory to the producer or Ending. If memory is unavailable or clearly unrelated, skip it. Show the route once and continue the same task through `workflow-skill` by launching its action in the same response turn.
- The entry is a bounded controller: it does not inspect task sources, duplicate downstream work, or combine collaboration and dispatcher execution for one branch. Every collaboration child starts with `LOCKED_ROUTE_NODE`. Classify the requested artifact, not inspected source language: a read-only Python/C#/Unity repository reconstruction remains a grounded answer in the project skill with `execution_domain=general`. Easy exact model work uses one producer plus a local deterministic Mini; grounded low-risk read-only answers use one producer by default. New plans use a 180-second easy or 600-second complex first-result deadline and at most one repair.
- Easy adaptive model fast path is one blocking `adaptive_model_runner.py --emit-result` call with one named profile preset and no help lookup, PTY, short polling loop, second result read, model Mini, or pre-result Real. The Task Analyze core contains the complete CLI and orchestration template: never inspect runner/history/receipt source or search memories/sessions for command examples. The wrapper canonicalizes an installed short skill name, derives the ladder, reads private experience, receipt-executes exactly its selected pair, runs any named grounded gate, and emits the passing result; the entry cannot supply a ladder or replace selection with a static choice. Never pass a source root with the `json-object` gate; only source-aware presets accept it. A bounded read-only child names its owner and passes `--ignore-user-config` instead of reloading the global entry contract; use deterministic `cwd/cache` outputs without discovery. Read-only execution uses shell `printf '%s'` piping, never a heredoc or `/tmp`. With `functions.exec`, set the outer yield to 60 seconds, use a 30-second launch, then 55-second `write_stdin` polls with no extra wait layer. When the runner and Mini pass, call no more tools or source checks and return its emitted result once immediately, not duplicated in commentary. One transport correction is allowed, and an unreceipted or fixed-pair child is never an adaptive fallback.
- Easy model routes show the exact text shape `Task Analyze -> direct task -> Mini Verify -> Main result -> Ending Task`, with model and effort on each model-executed node and `local | deterministic` / `deferred | no-op` on exact fast-path checks that do not execute or load `verify-skill`. Direct tool-only routes cover external app/tool state changes and one-command literal value/assignment/file-state extraction whose whole answer is deterministic tool evidence; they cannot interpret control flow, summarize semantics, author code/prose, or make judgment. Other source answers need an adaptive receipt. Complex tasks show a task-specific Mermaid workflow plus a numbered `Workflow with models` list.
- Show only the human route. Never emit a machine plan or internal plan marker in the answer. Complexity alone does not require dispatch: one result producer plus local Mini uses one direct receipt call. Use a private dispatcher plan only for a real graph with at least two model-executed result/verification nodes, and never inspect dispatcher source or fixtures to build it.
- Every active registry-owned code-domain implementation and authored probe loads `code-skill` and follows its domain rules. Spark-low is first only for obvious bounded low-risk easy low-ambiguity text-only tiny text/code/command work; its route is exactly Spark-low plus the full normal fallback ladder. Every non-tiny model route carries the exact full Luna/Terra/Sol ladder with no Spark. Current code examples are Python, plain C#, and Unity C#; `code_unspecified` is migration/history-only.
- Every downstream model node runs through a selectable surface with `LOCKED_ROUTE_NODE`. Every non-dispatched adaptive producer uses a stable preset through `task-analyze-skill/scripts/adaptive_model_runner.py`, which derives the exact ladder, selects from history, invokes `model_execution_receipt.py` once, and fails closed. A dispatcher adaptive producer must freshly recompute and match its locked learner recommendation immediately before execution. Only fixed nodes and fixed-pair benchmark baselines call the receipt runner directly outside entry context. A node without matching runtime proof is `planned only`.
- An outer `model_execution_receipt.py --entry-task` launch installs an inherited entry-context marker. Inside it, result producers require either `adaptive_model_runner.py` authorization or distinct dispatcher authorization backed by a fresh exact learner-recommendation match; a direct fixed or forged result receipt or recursive entry launch fails before `codex exec`. Dispatcher verification, repair, and ending roles use separate matching authorization. Authorization failures are non-retryable, and receipts expose only sanitized role/authorization metadata.
- Mini Verify gates the first result. Enforce `run-plan` -> read Mini-passed result -> show the self-contained basically verified result -> `release-main-result <handoff>` -> `run-ending <handoff>`. Ending Task must never be released before the result is actually shown. A later correctness failure notifies and reopens.
- If a nested/non-interactive execution surface buffers output, return the Mini-passed result with Ending pending; never run model Real Verify merely to fill one final response. Literal source/schema/string/syntax checks use local Mini evidence with no fabricated model receipt.
- First Result Principle: finish the requested task, run the smallest meaningful Mini Verify, and show the basically verified result immediately. Deeper proof belongs in Ending Task; if later correctness verification fails, notify, reopen, repair, rerun Mini Verify, and show the corrected result. Mini Verify is never exhaustive proof.
- For one obvious reversible action with no graph, execute its installed tool skill directly after the route and verify the observable state. Use no cached plan, child model, runtime model receipt, or adaptive producer sample for tool-only work. Model-executed nodes retain model|effort and receipt evidence. Complex work uses locked dispatched nodes, topology, receipts, Mini Verify, Main Result, then Ending Task.
- For a strategy A/B, keep workload, cwd, sandbox, user/project configuration, output contract, and acceptance identical. The fixed baseline stays outside entry context and uses `LOCKED_ROUTE_NODE` on the entry pair to bypass only Task Analyze; never use `--ignore-user-config` as the baseline. Count the entry plus unique descendant receipts once, use critical-path time, and treat timeouts as failed lower-bound arms.
- Consult private adaptive-routing history in local `model_experience.json` only after owner/domain and static floors. Categories/model roles are cold-start hints only; move effort first, then model, and reverse that order when upgrading. Correctness/quality gates eligibility. Cost ranking requires complete Real-passing evidence for at least two pairs in the same exact `workload_prompt_sha256` cohort; then minimize tokens, time, and weaker rung. Cross-workload or incomplete evidence falls back to the quality boundary. A frozen exact-profile `selected_pair` is reused with `trial=false` until verified failure or ladder/hard-floor/profile drift. `mini_real` Mini pass is provisional; Ending Real updates the same producer run, recomputes/persists `best_pair`, and returns routing learning. Operational and unverified failures are neutral diagnostics.
- Local history is generated if missing, never mirrored, and stores controlled profiles, generalized summaries, explicit success/failed model ranges, receipt proof, prompt-free workload hashes, verdicts, tokens, and timing only. Raw prompts, results, paths, secrets, and private task content are forbidden.
- After the result, Ending Task updates only related sanitized memory. Write readable model-switch lessons to optional Obsidian `TaskModelExperience/` after Real Verify; keep private `model_experience.json` as the exact machine routing authority. Missing memory providers are a successful no-op.
- If this task-start rule is missed, stop before further side effects, show the corrected route, and continue under the selected downstream models.

Do not restart Task Analyze for a bounded child prompt containing `LOCKED_ROUTE_NODE` or a direct `ENDING_TASK_WORKER` prompt. Those nodes obey the existing route and may not redesign it.

When this entry rule is combined with a broader global memory rule, Task Analyze preflight is exempt from full vault/project bootstrap. Only the bounded bridge query runs at entry; full reads belong to the selected producer or Ending.
