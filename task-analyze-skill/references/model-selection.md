# Model selection

The user's selected model and effort are authoritative for tasks with governing skills and for memory summaries. The runtime receipt proves executed identity. Only `gpt-6-luna`, `gpt-6-sol`, and `gpt-6-astra` are active routes. "Light" means provider effort `low`; Luna currently supports up to `max`, while Sol and Astra support `ultra`. Reject an unsupported pair clearly.

Only independent subtasks may use the cached capability ladder and verified same-project outcomes. Choose Luna for bounded work, Sol for general implementation, and Astra for demanding reasoning when the task evidence supports it. Adjust effort to the work and provider capability. Do not transfer another project's outcomes or use an unverified history record to claim quality or savings.

`selected_model_policy.py` enforces selected pairs. `bind_node` removes automatic fallback from governed work; `recommendation` returns the selected pair without querying adaptive history. `sync_model_capabilities.py --update` refreshes the three-model snapshot only during an authorized model/skill update.

See [adaptive routing](adaptive-routing.md) for learning and [runtime receipts](runtime-receipts.md) for evidence.
