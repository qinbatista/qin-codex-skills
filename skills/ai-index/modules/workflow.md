# Workflow

Start at [SKILL.md](../../../workflow-skill/SKILL.md) and select the relevant reference. Entry helpers are [task_artifact_paths.py](../../../workflow-skill/scripts/task_artifact_paths.py) for project Cache run allocation, [task_cache_cleanup.py](../../../workflow-skill/scripts/task_cache_cleanup.py) for identity-bound checkpoints, [task_resource_ledger.py](../../../workflow-skill/scripts/task_resource_ledger.py) for multi-consumer ownership, and [ending_resource_audit.py](../../../workflow-skill/scripts/ending_resource_audit.py) for residual audits.

Workflow owns readiness, bounded waits, Git branch/delivery rules, browser surfaces and resource cleanup. Its [bounded text and log reading](../../../workflow-skill/references/text-and-log-reading.md) starts machine diagnostics at the latest page, then follows keyword matches and necessary context; Code and Verify route to this owner. Keep memory contents with Project Memory and verification acceptance with Verify. Review [execution rules](../rules/execution.md) for mandatory Cache/quiet/cleanup boundaries. Native ownership and fresh consumer checks govern deletion; an active chat alone does not retain completed scratch.

Git tasks first resolve project-specific branch policy. The shared default starts on the repository's verified `master` or `main` and isolates collisions or required independent work in a minimal local worktree. Refresh the upstream before commits. Resolve integration conflicts from the source and tests in the active task, then verify, land and deliver the combined result before releasing the task checkout and branch. [Git branch ownership](../../../workflow-skill/SKILL.md#git-branch-ownership) · [Worktree isolation](../../../workflow-skill/SKILL.md#worktree-isolation) · [Conflict recovery](../../../workflow-skill/SKILL.md#resolve-integration-conflicts)

Follow [linear local updates](../../../workflow-skill/SKILL.md#linear-local-updates) for manual pulls, background workers and delivery. Fetch the configured upstream, fast-forward upstream-only updates and rebase verified unpublished commits when histories diverge. Published-history flattening requires an explicit request and native readback. Pulling a deliberately flattened branch requires a verified old-to-new base before replaying newer local commits.

For image generation, [image-generation.md](../../../workflow-skill/references/image-generation.md) binds the completed provider request to the unchanged native download SHA. Release that generation slot before QA, and record publication intent only after the resource owner admits the image.

Use the Cache cleanup plan to name verified final destinations and the exact inputs with a continuing consumer and end condition. Deliver disposable scratch immediately after output readback. Check identity and consumers before releasing retained resources. Automatic expiry applies to abandoned runs after 48 idle hours and fresh creator, descendant and native consumer checks. A recorded user hold survives expiry until the exact owner releases it. Keep source snapshots limited to their allowlist.

Use `task_cache_cleanup.py sweep` for a [daily or manual multi-project pass](../../../workflow-skill/references/cache-cleanup.md#daily-multi-project-sweep). Deduplicate aliases by filesystem identity, then run each project's guarded checkpoint and inventory unregistered Cache. Register proven legacy scratch with `--skip-cache-index` during the sweep. Process completed or resumable cleanup first, then evaluate older runs. Keep native pending reasons and confirmed deletion totals in the result.

For a retry of the same task, `task_artifact_paths.py --create --continue-from PREVIOUS_ROOT` transfers the named input files into a fresh run and verifies closure of the exact predecessor before returning its environment. In `task_cache_cleanup.py`, `prepare_run_continuation` binds the verified successor to the cleanup proof and `claim_run_continuation` resumes it with the same input selection. `test_cli_continuation_transfers_selected_inputs_and_removes_each_predecessor` in `test_task_cache_cleanup.py` checks repeated native cleanup and independent same-task siblings.

Windows cleanup checks each owned file and directory through native open-process IDs and readable process arguments before removing a run. Query failures keep the run pending. Tests remain in `workflow-skill/tests/`, registered by the [testing Skill](../../../.agents/skills/testing-skill/SKILL.md). Read Code's platform helper only for subprocess/portability changes; read Project Memory for Ending handoff/deletion, not ordinary scratch allocation.

Legacy external ledgers remain cleanup inputs after project Cache allocation is restored. Checkpoints inspect only this project's run records in the shared default ledger; custom old stores require an explicit cleanup-only base. New output and registration stay project-owned. macOS remount reconciliation requires the originally recorded native volume UUID plus the unchanged inode; absent original proof remains pending.

macOS Cache creation and allocation verify native Time Machine exclusion before task or registry writes. The allocator accepts a link-free native path spelling only for the same unchanged directory identity, avoids changing an already excluded ancestor, and fails closed when sticky exclusion cannot be verified. Recreating Cache through the allocator restores that check; Git ignore remains a separate boundary.

Interrupted deletion resumes from its persisted original member/change-identity proof, with fresh bounds and native consumers; new or altered inputs remain protected. Completed disposable runs may contain internal symlinks or closed FIFO/socket nodes: the cleanup helper unlinks these without following them after native consumer checks, while rejecting escaping links, reparse points, hard links, mounts and device nodes. Parent and child registrations cannot bypass each other: close independent descendants before deleting their parent. Explicit completed owners close before foreign scans and report `requested_complete`. Native lock storage and pending writes are bounded. Shared test fixtures close their own registration on every exit, while borrowed outer owners remain intact. Follow the cleanup helper targets and its real child-process crash regression.

Scan, discovery and allocation checkpoints expose direct `remote-*` children for native owner review, excluding the operational registry. Naming never proves retention or synchronization; verify real long-term configuration/asset/service consumers and retire consumed test payloads through existing guards. Allocation diagnostics keep a total and bounded path sample without traversing payload trees.

Default unclear new Cache output and all intermediates to `temp-*`, including output from `remote-*` code. Reserve `remote-*` for the current files allowed by a Git-tracked synchronization contract with a lasting consumer. Use the native owner for publication and readback. Preserve separately owned canonical history and active runtime state.

A current-project Cache checkpoint refreshes the bounded operational [Cache index](../cache/README.md) after registration, retention changes and deletion. The 48-hour rule only recovers abandoned task input runs; current native consumers and formal durable owners still govern their exact data. New local control registries use temp-task-cache-registry; existing remote-task-cache-registry remains local compatibility state while its lock domain is live.
