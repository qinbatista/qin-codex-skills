# Management

The [global plugin release](plugin-release.md) owns the portable bundle and its Git Marketplace. The `install-skill-pack-group` target owns the direct global path and whole-pack replacement. The legacy installer serves explicitly requested loose-Skill maintenance and global AGENTS changes.

Start at [SKILL.md](../../../management-skill/SKILL.md). Select [project_ai_index.py](../../../management-skill/scripts/project_ai_index.py) and its [contract](../../../management-skill/references/project-ai-index.md) for automatic project guidance; [repair_user_skill_root.py](../../../management-skill/scripts/repair_user_skill_root.py) for encountered directory repair; [sync_global_skills.py](../../../management-skill/scripts/sync_global_skills.py) for installation/publication; or [global_skill_regression_gate.py](../../../management-skill/scripts/global_skill_regression_gate.py) for release acceptance.

Management owns reusable authoring rules, single installation roots, recoverable replacement, candidate selection and authorized publication. Follow [repository rules](../rules/repository.md). The AI index is a project Skill, never a ninth managed global Skill or plugin Skill. The helper checks structure/paths/preimages/evidence; the agent still verifies ownership semantics. For method navigation, select `index-route` → `route_module`; it validates through `index-validation` and `target-validation`, then resolves one current anchor. `index-plan` guards route updates. The related `target-cli-test`, `target-failure-test` and `target-metadata-test` targets own behavior evidence. Use the target menu and follow only relevant relationship reasons. Ordinary index work does not need auth-profile files or private state.

[Capability catalog](../../../management-skill/assets/global-skill-capability-catalog.json) and [README templates](../../../management-skill/assets/readme) own release capability/README inputs. The README task flow describes a required index update for every project-changing task and inline guidance, memory and resource closeout; Codex chats remain user-managed. Update affected templates and generated README files together when that behavior changes. Tests stay in `management-skill/tests/`, tracked by the [project testing Skill](../../../.agents/skills/testing-skill/SKILL.md); installation and push retain their existing authorization boundaries.

AI-index gates apply only to the current task project. Reference lookups skip every CLI/API entry point before index or plan reads and writes. Select `index-scope` and `index-reference-test` for this boundary. `index-startup` and `index-directory` use `index-presence` before opening guidance. The visible index remains authoritative, including when partial. Only a project with neither index directory needs first-bootstrap consent. Existing indexes receive focused repair and expansion. Use `index-repair-test` for real CLI repair coverage and `index-validation` for guarded `index-plan` updates.

The mandatory startup question and every-project-change index update rule enter through Task Analyze's portable global AGENTS asset. `sync_global_skills.py install-global-agents --startup-only` installs only its managed startup block with a recoverable backup; ordinary deployment preserves global instructions and reports activation gaps. Install the updated managed Skills as well so their closeout instructions agree. Verify the real fresh-session question as well as helper output; do not infer activation from Skill installation.

Installer, release-candidate, per-check and diagnostic probe support has an explicit project Cache owner. Windows publication borrows its registered outer run for shallow isolated release candidates and short Git remote fixtures; each candidate still owns its test output and Cache ignore rule. The publication Git check accepts native CRLF while retaining trailing-space checks. Use the source targets for inside-out closure and cross-candidate environment binding. Shared test fixtures close both their run and registration; borrowed owners remain intact. Cleanup failures preserve their exact reason and the original operation failure.

Installer memory reporting uses the `installer-memory-check` target and always passes `--existing-only`; missing memory stays pending without creating a vault or parent. Its real subprocess regression checks this boundary. `test-default-temp-owner` binds default Python temp allocation and child temporary environment to the fixture, so installer tests remain project-local without caller-supplied TMP variables.

The `cache-index-sync` target owns `cache --apply`. It preserves authored guidance and owner mappings and replaces the ignored inventory from shallow Cache children and task records. It lists remote candidates as `remote_requires_review` and preserves metadata for native verification. `cache-index-test` covers real CLI refresh, this review boundary, vanished paths, idempotence and read-only inspection. `cache-index-boundary-test` covers bounded inventory and protected payloads. Read the [Cache management contract](../../../management-skill/references/project-ai-index.md#current-cache-management) before changing this boundary.

For [AI Index Compression](../../../management-skill/references/project-ai-index.md#ai-index-compression), select `index-compression` for read-only detection and `index-compression-test` for real detection and guarded apply coverage. Review guidance and exact-owner memory before guarded writes.

The `installer-closeout-merge`, `installer-closeout-status` and `installer-closeout-install` targets own explicit quiet-closeout repair. `install-global-agents --closeout-only` replaces one recognized legacy Ending paragraph or the managed inline block with a recoverable backup while preserving other global rules and vault routing. Ordinary deployment reports stale closeout activation separately without rewriting user guidance. `installer-closeout-real-test` executes the actual CLI and exact backup restoration; existing chats may retain old injected instructions.

Installer lock recovery distinguishes a lock that disappeared during release from an existing unsafe entry. Use the `installer-lock-observation` target and exercise the concurrent wait and disappearing directory cases when changing it.
