# Resource ownership

Apply the [external artifact policy](project-cache-artifact-policy.md) before acquisition: each request or test/build/package/deploy unit gets a fresh external run, even within one chat/task. Track exact temporary files, runtimes and UI surfaces when cleanup needs coordination. Reuse optional `scripts/task_resource_ledger.py` for multi-consumer ownership, durable handoff and run-root finalization; ordinary work needs no extra ledger. New ledgers bind the exact task and `run_id`. Legacy deterministic roots support readback and original-owner cleanup, never new write reuse; project-Cache ledgers remain read-only under their migration/cleanup boundary.

Image jobs follow [image generation and closure](image-generation.md). Downloads move immediately to the bound owner; verified acceptance and synchronization release disposable transport copies. Confirmed account-action submission and bounded final tab cleanup do not gate independent work. Keep backend deletion, tab closure and scratch absence as separate verified or pending states; preserve exact recovery targets without endless readback loops.

At each unit's completion, place final deliverables in their declared output, website or resource owner. Update references and verify bytes and the consuming reader from a fresh process or website request. A receipt inside scratch alone is not delivery. Close unused owned browser tabs, previews, terminals, windows, servers, workers, subscriptions, transfers and connections through their owners after readback. Stop activity before removing backing files. Delete that run's disposable support and test/build intermediates, including empty run directories and completed ledgers/markers. Do not wait for the chat, later units or Ending to finish. Keep requested packages, images, documents, data, memories, review/test projects and reusable mobile simulations in their actual owner; preserve backing files and live surfaces while needed.

For a continuation, allocate a new run and follow the policy's [selective input handoff](project-cache-artifact-policy.md#separate-executions-and-continuation). For a ledger-backed destination, reserve each absent input path (or its containing directory tree) with `acquire_path` before copying, track created parent directories, then `seal_path` after byte readback; copied inputs must remain recorded so the next run can also finalize. Verify useful copied inputs and consuming paths before releasing their old dependencies. A running project/chat or a new unit with the same task ID does not protect unrelated old runs. Preserve only exact active, recovery, shared or review/reuse resources; an uncertain consumer blocks the affected item, not all siblings.

On pause or failure, transfer only the minimum inputs and resumable state required for recovery to the exact declared recovery owner, verify them, and remove independent disposable scratch. Preserve useful review/reuse resources even when retention metadata is missing, then establish their owner without breaking references. Completed disposable evidence never authorizes indefinite temp retention. Consumers that need the result must be rebound to the verified durable owner; renaming a temp directory to `remote-*` is not a handoff. A verified `Cache/remote-*` is retained under its actual resource owner, not merely its prefix.

Release disposable resources in reverse acquisition order. Resolve and bounds-check every deletion target against the exact task root; use one native platform shell end to end or the portable helper, never shell-built path lists. Do not traverse symlinks/reparse points or remove unrelated, pre-existing, shared, or Unity-owned resources. Ownership or identity conflicts block only the affected cleanup and must be reported precisely; they are not a review/debug retention exception. The ledger's `durable-handoff` verifies a real owner record and bytes before releasing scratch dependencies; `finalize` removes an exact empty task root only after all recorded resources are closed and no unknown files remain.

## Worktrees and disposable checkouts

Release a unit's disposable build/test checkout when verified output no longer needs it. For a source worktree, first commit task-owned changes, integrate/deliver them to the authorized branch and verify any required remote hash. Inspect the exact worktree, branch, dirty/index state and current consumers immediately before removal. Preserve unrelated edits, uncommitted work and explicitly retained checkouts; move required outputs or minimum recovery files to their verified owner first.

Use `git worktree remove` for a clean ordinary worktree, or Codex's `archive_worktree` for its exact attached managed owner; the latter retains a recoverable snapshot while removing the checkout. Use the owner's native removal for a disposable clone. Never force-remove a dirty worktree or delete its directory behind Git/Codex. Read back checkout absence and worktree registration, then remove only task-created eligible `codex/*` branches whose commits are safely delivered. An active chat does not justify keeping an unused earlier worktree; an active consumer of that checkout does.

Cleanup never controls, interrupts, archives, or deletes another Codex task/session, user-opened tab, or Codex-managed session record. Ending records Obsidian memory and runs the [bounded resource audit](ending-resource-audit.md) in parallel after the main result. It can release confirmed disposable resources from completed runs through their original owners, including earlier units of a still-running chat, without becoming a consumer or delaying producer cleanup. Its own completed conversation is removed separately through supported native actions under [Project Memory](../../project-memory-skill/SKILL.md#ending-conversation-cleanup), after both branch readbacks; direct session-file/database purges remain forbidden. Recheck exact run/resource liveness and purpose before release; protect active/shared resources and the user's Codex experience. Follow the owning Skill first, then finish safe missed cleanup or report precise pending items.
