# Resource ownership

Track exact temporary files, runtimes, and UI surfaces created for this task when cleanup needs coordination. Reuse the optional `scripts/task_resource_ledger.py` for multi-consumer ownership, durable handoff, and exact task-root finalization; ordinary work needs no extra ledger.

Image jobs close individually under [image generation and closure](image-generation.md). Downloads move immediately to the bound resource owner; verified synchronization and acceptance release scratch and transport duplicates without waiting for the larger task to finish. Exact account deletion/readback and owned-tab closure gate the next image job; blocked cleanup remains pending.

Before completion, place final deliverables in their declared output, website, or resource owner. Update every durable reference and verify actual bytes and the consuming reader from a fresh process or website request, as applicable. A receipt inside scratch alone is not durable delivery. Close task-owned browser tabs, previews, windows, servers, and processes through their owning tools after the last needed readback. Delete exact task-owned verification files, disposable tests, previews, intermediates, and `Cache/temp-*` scratch or `Cache/tmp-*` scratch, including the task directory and its completed ledger/markers. Keep a requested package in its declared deliverable owner, not temp.

On pause or failure, transfer only the minimum inputs and resumable state required for recovery to the exact declared recovery owner, verify them, and remove remaining scratch. Evidence, review, debugging, retry, or a possible downstream consumer never authorizes indefinite temp retention. Consumers that need the result must be rebound to the verified durable owner; renaming a temp directory to `remote-*` is not a handoff. A verified `Cache/remote-*` is retained under its actual resource owner, not merely its prefix.

Release disposable resources in reverse acquisition order. Resolve and bounds-check every deletion target against the exact task root; use one native platform shell end to end or the portable helper, never shell-built path lists. Do not traverse symlinks/reparse points or remove unrelated, pre-existing, shared, or Unity-owned resources. Ownership or identity conflicts block only the affected cleanup and must be reported precisely; they are not a review/debug retention exception. The ledger's `durable-handoff` verifies a real owner record and bytes before releasing scratch dependencies; `finalize` removes an exact empty task root only after all recorded resources are closed and no unknown files remain.

Cleanup never controls, interrupts, archives, or deletes another Codex task/session, user-opened tab, or Codex-managed session record. Ending records Obsidian memory after the main result and does not keep temporary resources alive or gate their cleanup.
