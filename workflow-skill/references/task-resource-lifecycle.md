# Resource ownership

Track exact temporary files, runtimes, and UI surfaces created for this task when cleanup needs coordination. Reuse the optional `scripts/task_resource_ledger.py` for multi-consumer ownership, durable handoff, and exact task-root finalization; ordinary work needs no extra ledger.

Image jobs follow [image generation and closure](image-generation.md). Downloads move immediately to the bound owner; verified acceptance and synchronization release disposable transport copies. Confirmed account-action submission and bounded final tab cleanup do not gate independent work. Keep backend deletion, tab closure and scratch absence as separate verified or pending states; preserve exact recovery targets without endless readback loops.

Before completion, place final deliverables in their declared output, website, or resource owner. Update every durable reference and verify actual bytes and the consuming reader from a fresh process or website request, as applicable. A receipt inside scratch alone is not durable delivery. Close unused task-owned browser tabs, previews, terminal panels, windows, servers, workers, subscriptions, transfers and connections through their owning tools after the last needed readback. Stop activity before deleting its backing files. Delete exact disposable verification files, test/build intermediates and `Cache/temp-<task>/` scratch, including empty task directories and completed ledger/markers. Keep requested packages, images, documents, data, memories, review/test projects and reusable mobile simulations in their actual deliverable/resource owner; preserve backing files and live surfaces while review, reuse or the user needs them.

On pause or failure, transfer only the minimum inputs and resumable state required for recovery to the exact declared recovery owner, verify them, and remove independent disposable scratch. Preserve useful review/reuse resources even when retention metadata is missing, then establish their owner without breaking references. Completed disposable evidence never authorizes indefinite temp retention. Consumers that need the result must be rebound to the verified durable owner; renaming a temp directory to `remote-*` is not a handoff. A verified `Cache/remote-*` is retained under its actual resource owner, not merely its prefix.

Release disposable resources in reverse acquisition order. Resolve and bounds-check every deletion target against the exact task root; use one native platform shell end to end or the portable helper, never shell-built path lists. Do not traverse symlinks/reparse points or remove unrelated, pre-existing, shared, or Unity-owned resources. Ownership or identity conflicts block only the affected cleanup and must be reported precisely; they are not a review/debug retention exception. The ledger's `durable-handoff` verifies a real owner record and bytes before releasing scratch dependencies; `finalize` removes an exact empty task root only after all recorded resources are closed and no unknown files remain.

Cleanup never controls, interrupts, archives, or deletes another Codex task/session, user-opened tab, or Codex-managed session record. Ending records Obsidian memory and runs the [bounded resource audit](ending-resource-audit.md) in parallel after the main result. It can release confirmed disposable resources from completed tasks through their original owners, without becoming a consumer or delaying producer cleanup. Recheck task liveness and purpose before release; protect active/shared resources and the user's Codex experience. Follow the owning Skill first, then finish safe missed cleanup or report precise pending items.
