# Workflow Routing Matrix

Use this matrix from `workflow-skill` before any worker skill starts. First show the user-facing start diagram required by `SKILL.md`; then use the matching route row. Every row begins with `workflow-skill`; the remaining skills are executors selected by it. These rows are multi-select routes: combine them when the task spans several artifact types, but do not run unrelated rows as a checklist.

## Prompt Task Gate

Before selecting the `text`, `code`, `python`, or `mixed` row, check whether the request is actually about prompt behavior. Match the prompt route when the user mentions prompt wording, prompt files/templates/strings/constants, system/developer/user instructions, model or agent instructions, AI output behavior, extraction/generation/checker prompts, prompt tests, prompt review, or a prompt/rule that is not triggering.

Prompt route takes precedence over generic text work. If the prompt is embedded inside Python/C# executable behavior, combine the relevant code route with the prompt route instead of dropping the prompt workflow.

## Goal Check Rules

- Every route starts with `workflow-skill`; all later skills are executors.
- Every workflow-skill task starts with a user-facing start diagram: compact direct-route diagram for lightweight work, or task-specific Mermaid diagram plus target map for explicit work.
- For Python/C# executable behavior, the order must be `code-skill -> verify-skill`.
- Run the Prompt Task Gate before generic text/code routing. For any standalone prompt-related task, use the prompt route; start by showing `Prompt idea -> Prompt goal -> Problems -> Solution`; add `code-skill` only when the prompt is being embedded in Python or C# executable code.
- For global skill work, run `management-skill` before edits and after successful verification when the user asks to push; use its internal GitHub sync route.
- Passing evidence must include real `Input`, `Used`, `Output`, and `Why Pass` when a report is generated.
- If the observed output does not satisfy the goal target, continue the loop instead of finishing.
- After a user-facing task passes, run `optimization-skill` only when the user explicitly asks, the same workflow has repeated at least three times, or the workflow is clearly stable and likely reusable. Verify optimized behavior again through `verify-skill`.
