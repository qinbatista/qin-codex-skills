# Management Skill

Do not load this skill for ordinary exact-scoped read-only work or Direct/Global benchmark worker arms. Use it directly only for an explicit routing-record, Codex profile, or approved mirror-management request. When Task Analyze has explicitly activated and admitted a delegated route, Workflow may instead deliver a locked management node. It does not choose or silently replace a delegated model/effort pair.

## Internal Route Selection

Select only what the inline request or admitted locked plan requires:

- **Model-experience route**: inspect project-scoped recommendations/status or record an authorized Ending Real handoff through `../project-memory-skill/scripts/obsidian_model_memory.py`; inspect the old local routing JSON only when the user explicitly asks for legacy history.
- **Profile route**: inspect saved profiles, refresh login state, import/backup a profile, show sanitized status, or switch the active profile after explicit confirmation.
- **Global skill mirror route**: for an explicit install/update, skip inspect/gate/compare and enter the unconditional `deploy` or install-only `pull`/legacy `sync` path immediately; use inspect/status/gate/compare only for a separately requested diagnostic, and use `push` only to publish the maintained source explicitly.
- Use multiple routes only when the inline request or admitted locked plan requires them.

## Commands

Use the maintained scripts instead of ad hoc profile or mirror logic:

- `scripts/manage_auth_profiles.py`
- `scripts/show_all_auth_status.py`
- `scripts/sync_global_skills.py`
- `scripts/global_skill_regression_gate.py`

The maintained Git repository is the publication source of truth; the installed global directory is a deployment target, never the source for repository edits. Run `sync_global_skills.py push --source-dir <repository-root> --message <message>` from that repository. Before its first README, index, commit, or remote mutation, the command runs the full retained-capability release gate exactly once. Only after PASS may it render both root READMEs, commit the authorized source including the compact root `AGENTS.md`, push the current branch, verify the remote branch hash equals local `HEAD`, and require a clean worktree. It must not report success while the maintained source is still an uncommitted or unpushed copy.

Use `sync_global_skills.py deploy --source-dir <repository-root> --skills-dir <global-skills-directory>` for an explicit local installation from the maintained repository source. Acquire one cross-process target lock and wait boundedly for an active installer, recover any dead interrupted transaction from its fsynced manifest, materialize the eight required source trees, move each old managed Skill into a recoverable opaque backup without traversing files, symlinks, or junctions, replace those managed Skills, and return. Preserve user global `AGENTS.md` files, unrelated local Skills, and opaque `task-analyze-skill/local/` state. Only source availability, recoverable backup, safe exact-target writes, or a still-active conflicting writer may stop replacement; they are mechanical prerequisites, not quality gates or user-assigned validation work.

Consumer `deploy`, `pull`, and legacy `sync` stop after safe replacement. A `pull` shallow-clones the latest published source; `deploy` uses the supplied published checkout. Neither path loads routing, invokes validators, scans public safety, compares content, hashes a whole tree, runs platform/regression/parity/attestation checks, or creates an Ending. Failures in download, materialization, backup, or writing restore the previous Skill targets; unrelated local Skills, user global `AGENTS.md`, and opaque `task-analyze-skill/local/` remain untouched. Local deployment never publishes to GitHub.

`sync_global_skills.py status --source-dir <repository-root> --skills-dir <global-skills-directory>` compares repository source with both the remote branch and the deployed managed Skill folders, and exits nonzero on managed-Skill deployment drift. User global `AGENTS.md` is intentionally outside this parity check. Use `install-global-agents` only when replacing the documented Codex global template is deliberate; it creates a persistent backup, `list-global-agents-backups` shows recovery IDs, and `restore-global-agents --backup-id <id>` restores one exact prior entry. `bridge-user-skills` previews the documented user-Skill-path links by default and changes nothing without `--apply`.

Use snapshot/dry-run/status modes for testing. Do not call `sync` or `push` in a task that was authorized only to edit/test local skills.
