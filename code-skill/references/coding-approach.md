# Coding Approach and UI Preferences

Use [code-writing philosophy](code-writing-philosophy.md) for ownership, scope, naming, and direct code. Define success before editing and state assumptions only when they affect the result. Use plain `if`/`else` for two mutually exclusive outcomes and an appropriate switch-style construct for three or more.

For any UI or visual presentation, apply the [shared readable UI rules](../../workflow-skill/references/readable-ui.md). This single source covers websites, tools, PDF reports, documents, and slide presentations, including work without code changes. It owns compact horizontal layouts, grouping, labels, density, typography, containment, interaction states, and rendered checks.

Use a visual aid only when it clarifies information, and preserve essential meaning in accessible text. Follow relevant project preferences without borrowing another project's design.
