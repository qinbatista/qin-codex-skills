# qin-codex-skills

- This repository owns the eight public global skills. Each skill owns its instructions, references, runtime helpers, and non-runtime tests needed by the clean-clone release gate. Prune duplicate or retired tests when goals change; project-specific implementations belong in project skills.
- The user's selected model and effort read applicable skills and relevant project memory, define goals, and perform skill-governed work. Only genuinely skill-independent tasks use adaptive model selection. Mechanical tool calls need no extra model.
- Disclose score/band, selected model/effort and route early, then delegated goals, scores, pairs, dependencies and actual outcomes. Distinguish assignments from runtime proof. Plan only when useful. Parallel branches need disjoint ownership and explicit dependencies. The root integrates and completes the task.
- Verify changed code and consequential results inside the active task with one real behavior check or output readback. A quick check or mock is not acceptance. Do not start or compile a whole project unless requested.
- Ensure a real Obsidian memory vault through `project-memory-skill/scripts/obsidian_vault_setup.py` before recall or memory writes. If none exists, generate it from `qinbatista/qin-llm-wiki` outside Codex and project folders; report its exact path and tell the user to back up the whole vault regularly because it holds all Codex and project memory. If setup fails, leave writes pending without a local fallback. Missing matching project notes are a normal read skip.
- On a replacement computer, restore or sync the existing whole vault first. A registered or configured vault that is unavailable remains pending; never create an empty replacement. The public generator is a first-vault template, not a private-memory backup.
- Durable memory belongs only in the configured Obsidian vault, organized under its project or explicitly shared owner. Never write memory, pending queues, routing history, coverage records, memory path pointers, or time-varying project information under Codex's local folders or project Cache. Project `AGENTS.md` and Skills contain stable operating rules and how the project works, not a changing memory log. Review and update their relevant rules when the rule itself changes.
- Ending only updates Obsidian memory with the user's selected model and effort after the main task and real verification complete. Create one separate visible projectless memory task when useful, leave it unpinned in recent tasks, and read back the vault result. Its status does not gate the main task or another active task. It never tests, repairs, benchmarks, publishes, or creates task chains. No useful memory is an explicit skip; unavailable task creation or vault stays pending.
- Read only relevant project memory and explicitly shared preferences. Missing matching notes are a normal skip after vault setup. Preserve project isolation, useful history, privacy, and unrelated edits.
- `task-analyze-skill` owns model policy and runners; `workflow-skill` owns coordination; `verify-skill` owns in-task evidence; `project-memory-skill` owns recall and durable summaries.
- `management-skill/scripts/sync_global_skills.py` owns installation and publication. Install with locking, recoverable backup, and rollback; preserve unrelated skills, user AGENTS, and private routing history. Update global AGENTS only when authorized. Publish only when requested, after the release gate.
- Follow [portable, quiet execution](code-skill/references/skill-platform-compatibility.md) for scripts, tests, and background work: prefer Python, preserve supported platform differences, and capture output without opening windows. Nested Codex uses `approval_policy="never"`; never click an approval prompt or restart another task.
- Keep disposable, test, and uncertain support artifacts in task-owned `Cache/temp-*`; remove them and close task-opened surfaces after final readback when no review or debugging depends on them. Move retained tests to `Cache/remote-*` only if they run there and need not ship; otherwise keep them in versioned non-runtime test areas. Only `temp-*` and `remote-*` belong directly under Cache. Code and configuration use portable relative paths. Never auto-clean `Cache/remote-*`; record project use, reason, owner, and pending sync destination.
- `Cache/remote-ai-paths/registry.json` is the ignored AI-only non-memory test fixture path registry; owner: `management-skill`; retain for fixture discovery; sync destination pending. Obsidian memory paths are never stored there.
- `Cache/remote-test/` holds regression and routing evidence; owners: `management-skill` and `task-analyze-skill`; retain for release and model-routing review; sync destination pending.
- Definition of done: current instructions and executable behavior agree, relevant tests pass, and source/install/publication status is reported accurately.
