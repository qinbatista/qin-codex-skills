# qin-codex-skills

- This repository owns the eight public global skills. Each skill owns its instructions, references, runtime helpers, and non-runtime tests needed by the clean-clone release gate. Prune duplicate or retired tests when goals change; project-specific implementations belong in project skills.
- Install user Skills in `~/.agents/skills` and project Skills in the project's `.agents/skills`. `CODEX_HOME` owns configuration, global `AGENTS.md`, and bundled resources. Use `management-skill` for recoverable legacy directory and reference repair.
- Apply [Skill authoring rules](management-skill/SKILL.md#authoring-rules) when creating or revising Skills: keep stable rules and essential workflow, simplify steps, reuse local code for deterministic mechanics, and put per-run support data in task-owned Cache. Ordinary task completion does not trigger a Skill update; durable project facts belong in central memory.
- Before any file write, apply the [Cache policy](workflow-skill/references/project-cache-artifact-policy.md): every temporary file goes only into ignored `Cache/temp-<task>/` from its first write, including screenshots, JSON receipts, test output, and delegated work. Inspect exact paths and the Git index before staging or committing; temporary files never enter Git. Projectless work uses its current workspace's Cache, with no system Temp or Codex session fallback.
- Preview the result, qualitative difficulty, known model assignments, parallel branch roles and real dependencies. Start ready independent work promptly; prepare downstream work during external waits and bound stale-client checks. Confirmed submission unblocks independent work without claiming backend completion. Follow Workflow's ready-work policy and close unused owned tabs at final cleanup. Ask only for materially missing information or required authorization.
- Enforce [mandatory visible Skill reporting](task-analyze-skill/SKILL.md#mandatory-visible-skill-reporting): every startup/resumed turn before tools, every progress update and phase transition, and every final response must show exact Skill names with short purposes, including delegated use. Announce new selections before use, distinguish planned from applied Skills, report none/missing/unused honestly, and correct omissions before continuing. Brevity never waives this rule.
- Verify changed code and consequential results inside the active task with one real behavior check or output readback. A quick check or mock is not acceptance. Do not start or compile a whole project unless requested.
- Before creating a maintained Python test file or running extended project testing, read [this project's testing-skill](.agents/skills/testing-skill/SKILL.md). Its registry records test purposes, goals, levels, runners, and repository-relative paths. Keep each managed global Skill's clean-clone tests in its own `tests/` and track them in the project testing Skill; update or combine duplicate-purpose cases before adding new tests. Default to level 2 real affected-case verification.
- Ensure a real Obsidian memory vault through `project-memory-skill/scripts/obsidian_vault_setup.py` before recall or memory writes. If none exists, generate it from `qinbatista/qin-llm-wiki` outside Codex and project folders; report its exact path and tell the user to back up the whole vault regularly because it holds all Codex and project memory. If setup fails, leave writes pending without a local fallback. Missing matching project notes are a normal read skip.
- On a replacement computer, restore or sync the existing whole vault first. A registered or configured vault that is unavailable remains pending; never create an empty replacement. The public generator is a first-vault template, not a private-memory backup.
- Durable memory belongs only in the configured Obsidian vault. `Projects/<owner>/Memory.json` owns structured current knowledge and `Knowledge.md` is its readable view; the existing event store retains history. Keep architecture, module, file, and method knowledge addressable within that store without creating a file per entity or task. Never write memory, pending queues, coverage records, memory path pointers, or time-varying project information under Codex's local folders or project Cache. Project `AGENTS.md` and Skills contain stable operating rules, not a changing memory log; update their rules when the rules change.
- After the main result and real verification, one authorized visible projectless Ending runs useful Obsidian memory and [Workflow's resource audit](workflow-skill/references/ending-resource-audit.md) in parallel. Follow specific owners' cleanup first, then reclaim confirmed disposable resources from originating/recent completed tasks. Preserve active work, review/reuse files and live environments, shared resources and the user's Codex experience. Memory failure never blocks cleanup. Consolidate touched knowledge and check exact-project maintenance on every closeout, including no-change outcomes. Missing or invalidated synthesis for nonempty current knowledge is due immediately; 20 distinct writes or 30 days also trigger refresh. Complete due synthesis in the same Ending with eligible scoped facts and original evidence limits. Leave Ending unpinned in recent tasks, show its link and separate branch readbacks. It never gates other work, tests, repairs code, benchmarks, publishes or creates further visible tasks. Skip only unnecessary branches; unavailable task creation stays pending.
- Use `project-memory-skill/scripts/project_knowledge.py recall --project-root ROOT --vault VAULT` with exact module/file/symbol filters and explicitly shared preferences. Method recall requires a module, exactly one file, and one or more symbols. A missing index, missing entry, or owner conflict skips recall without broad fallback. Retired and superseded claims remain history. Stale entries and methods without source hashes cannot enter current context; methods without hashes return separately as unverified pointers. Source evidence is captured by the originating task, not retroactively upgraded by Ending. Cross-project relations are explicitly selected reference pointers and never merge another project's authority into this one. Preserve project isolation, useful history, privacy, and unrelated edits.
- `task-analyze-skill` owns the goal, implementation preview and [action completion rule](task-analyze-skill/SKILL.md#complete-action-requests); `workflow-skill` owns coordination and global resource cleanup; `verify-skill` owns in-task evidence; `project-memory-skill` owns recall, durable summaries and the visible Ending handoff.
- `management-skill/scripts/sync_global_skills.py` owns installation and publication. Install with locking, recoverable backup, and rollback; preserve unrelated skills, user AGENTS, and existing private history. Update global AGENTS only when authorized. Publish only when requested, after the release gate.
- For a Windows global Skill update, protect unrelated dirty work and pull the current published source before running Windows checks. Repair Windows-only defects in the maintained source, verify on both platforms, then publish and read back both checkouts and installations.
- After final verification, remove only the worktrees and `codex/*` branches created for that task, after confirming they are clean. Keep unrelated or explicitly retained branches and worktrees.
- Follow [portable, quiet execution](code-skill/references/skill-platform-compatibility.md) for scripts, tests, and background work: prefer Python, preserve supported platform differences, and capture output without opening windows. Never click an approval prompt or restart another task.
- Keep disposable support and test intermediates in exact task-owned `Cache/temp-<task>/`. Place requested results in their declared owner, update references and verify with a fresh reader; release unused task surfaces, process/network handles and exact disposable scratch, including empty roots. Preserve useful review/reuse files, documents, data, memories, test projects and mobile simulations with their backing/live resources; establish their owner before clearing scratch. On pause/failure keep minimum recovery state and clean independent disposable work. Renaming temp to `remote-*` alone does not establish ownership. Preserve unrelated work and retained resources. Follow owning helpers' bounded cleanup; shipping tests belong in versioned non-runtime test areas. Code/configuration use portable relative paths.
- Definition of done: current instructions and executable behavior agree, relevant tests pass, and source/install/publication status is reported accurately.
