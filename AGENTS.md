# qin-codex-skills

## Scope and ownership

- This repository is the source for public Codex global Skills and lifecycle contracts.
- Each top-level Skill owns its `SKILL.md`, metadata, references, scripts, and focused tests.
- `management-skill` owns publication and runtime mirror deployment; do not treat a source edit as deployment.
- `task-analyze-skill` owns routing and receipts; `project-memory-skill` owns durable, sanitized project-change records.

## Stable entry points and constraints

- Classify material result stages before any producer. Exactly one stage uses `task-analyze-skill/scripts/obsidian_adaptive_model_runner.py`; two or more stages use one `dynamic_task_graph` and one `task_route_dispatcher.py run-plan`. A zero-argument `graph-route-required`/`route-required` result means no model ran and must never be retried as one producer.
- Require exactly one disclosed execution lifecycle for every routed result: eligible ultra-simple work executes directly; other single-result work plans then executes once; multi-result work plans and executes a dependency graph. Only same-topic quality/correctness failure strengthens its solver; operational failure is quality-neutral, and acceptance remains final-aggregate and surface-gated.
- Every complex/advanced task and existing `planned_graph` evaluates optional collaboration child sessions. Admit only two or more dependency-ready branches with explicit inputs/outputs and boundaries, pairwise-disjoint writes or isolated copies/worktrees, and expected wait reduction; otherwise retain the current runner/dispatcher with a bounded reason. One logical graph selects collaboration children or one dispatcher run, never both. The main session alone controls children and owns aggregation, acceptance, Quick Check, cancellation, and the final aggregate receipt; child readiness never completes the root task or starts Ending/Repair.
- Publish only through `management-skill/scripts/sync_global_skills.py` when authorized.
- Treat `management-skill/assets/global-skill-capability-catalog.json` as the retained global behavior authority. A consumer install/update performs only source-byte materialization, exact managed-source availability, cross-process locking with fsynced recovery, opaque recoverable backup, and safe exact-target replacement of every managed Skill; it preserves user global AGENTS files, unrelated Skills, and `task-analyze-skill/local/`. Only explicit global-AGENTS installation may write the documented Codex target, and it must create a persistent restorable backup first. Consumer deployment never performs routing, safety, platform, regression, parity, attestation, content-difference, Ending, or snapshot-hash work. GitHub commit/push runs the full release gate exactly once before README, index, commit, or remote mutation.
- Ending is a real-evidence and durable-memory lifecycle. Start one detached global projectless Ending when the released result exposes `real_test`, `information_update`, or `memory_update`, or when it is classified as a material structural, non-trivial code, conceptual, or process update. Every material update requires durable project-memory closeout; only an explicitly proven `trivial_value_only` edit with no other surface may record `intentionally_skipped_simple_task` and `ending_skip_reason=no_real_test_or_information_or_memory_or_material_update`. Launch only from the final aggregate producer receipt after every result node/subprocess has settled; a child receipt never starts an Ending. Its `create_thread` target is exactly `{"type":"projectless"}` with no project/current-task attachment, and `list_threads` readback must show `projectId=null` or absent before acknowledgement. Spark-xhigh is first priority. A real model quota, five-hour, provider-rate, or trusted retry-after failure is recorded durably with restriction and retry timestamps; while that model is cooling, the next Ending skips it and selects the next stronger supported controller, and Spark returns to first priority after cooldown. Never repeatedly retry a cooling model or turn a quality failure into a cooldown. Capability-routed Terra/Sol `ENDING_CHECK_WORKER` nodes may perform saved semantic checks without owning lifecycle or repair.
- Host execution is non-interactive and terminal-local: use the current `exec_command`/Python execution surface and never open Terminal.app, Computer Use, or a second terminal just to click Allow. Nested `codex exec` commands must set `approval_policy="never"` explicitly while retaining their declared sandbox. If a host UI still asks for Allow, stop the retry/relaunch loop and report a host-permission BLOCKED state; do not click or emulate the approval.
- Before durable work, compare the active Skill/AGENTS process contract, current execution evidence, and effective scoped project-result memory. Ending may append a superseding memory correction or reconcile its projection only for a proven memory defect. Any repairable Ending error or mismatch creates a fresh independent global projectless repair session; the immutable origin is evidence only. The repair session must never send to, steer, interrupt, terminate, hand off, move, or mutate any existing task/session. If an active task owns a required write surface, the repair session waits without interruption until that surface is released, then repairs within scope and starts a fresh independent Ending.
- `workflow-skill` owns Task Resource Lifecycle through `workflow-skill/references/task-resource-lifecycle.md`: record exact task-owned path/runtime/UI resources; after durable-result and last-consumer readback, release disposable resources in reverse acquisition order; retain or defer preexisting, shared, conflicted, Unity, date, and remote resources; resource cleanup never controls another Codex task, thread, session, or Ending.
- Keep support artifacts under `Cache/`; never embed machine-specific paths, secrets, or task history in Skill source.
- Keep `AGENTS.md` structural: ownership, entry points, hard constraints, conventions, and definition of done only.
- Cache top-level directories use only `tmp-<name>`, `remote-<name>`, or `<YYYYMMDD>`. One-task disposable artifacts and ordinary test scratch use `tmp-*`; `<YYYYMMDD>` requires a short-reuse reason and review point; `remote-*`/`remote-test/` require explicit retention. Reusable formal tests remain source tests. `Cache/cache_path.json` remains the reserved AI-only registry.
- Important Cache: `Cache/remote-test/unity-game-code-structure-design/` is the untracked portable structural-trial harness for the Unity game-code ownership reference; owner: `code-skill`; retain for focused local checks.
- Important Cache: `Cache/remote-test/global-skill-regression/` is the untracked current/cumulative release-gate report store; owner: `management-skill`; retain for non-regression audit history.

## Definition of done

- Preserve every retained capability, add focused regression coverage for durable behavior changes, and require the full release gate before publication.
