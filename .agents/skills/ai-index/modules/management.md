Start at [SKILL.md](../../../../management-skill/SKILL.md). Select [project_ai_index.py](../../../../management-skill/scripts/project_ai_index.py) and its [contract](../../../../management-skill/references/project-ai-index.md) for automatic project guidance; [repair_user_skill_root.py](../../../../management-skill/scripts/repair_user_skill_root.py) for encountered directory repair; [sync_global_skills.py](../../../../management-skill/scripts/sync_global_skills.py) for installation/publication; or [global_skill_regression_gate.py](../../../../management-skill/scripts/global_skill_regression_gate.py) for release acceptance.

Management owns reusable authoring rules, single installation roots, recoverable replacement, candidate selection and authorized publication. Follow [repository rules](../rules/repository.md). The AI index is a project Skill, never a ninth managed global Skill or plugin Skill. The helper checks structure/paths/preimages/evidence; the agent still verifies ownership semantics. For method navigation, select `index-route` → `route_module`; it validates through `index-validation` and `target-validation`, then resolves one current anchor. `index-plan` guards route updates. The related `target-cli-test`, `target-failure-test` and `target-metadata-test` targets own behavior evidence. Use the target menu and follow only relevant relationship reasons. Ordinary index work does not need auth-profile files or private state.

[Capability catalog](../../../../management-skill/assets/global-skill-capability-catalog.json) and [README templates](../../../../management-skill/assets/readme/) own release capability/README inputs. Tests stay in `management-skill/tests/`, tracked by the [project testing Skill](../../testing-skill/SKILL.md). Update affected templates and generated README files together when that behavior changes; no installation or push without its existing authorization.

AI-index gates and maintenance apply only to the current task project. Reading, searching or consulting other projects does not change that owner or prompt for their indexes. `--project-scope reference` (Python `project_scope="reference"`) skips every CLI/API entrypoint before index or plan reads and writes; `current` is the compatible default. Select `index-scope` and `index-reference-test` for this boundary. At current-project startup, the index helper checks presence before project discovery. The helper selects existing visible `skills/ai-index` first and otherwise the legacy `.agents/skills/ai-index`; partial visible indexes never fall back or recreate hidden duplicates. Only a project with neither index directory requires explicit first-bootstrap consent. Existing indexes, including partial or malformed ones, receive automatic focused repair and expansion; new modules, routes, documents and sub-indexes need no new creation question. Select `index-startup` and `index-presence` for this gate, with `index-repair-test` for real CLI repair coverage.

The mandatory startup question enters through Task Analyze's global AGENTS asset. `sync_global_skills.py install-global-agents --startup-only` installs only its managed startup block with a recoverable backup; ordinary deployment preserves global instructions and reports activation gaps. Verify the real fresh-session question as well as helper output; do not infer activation from Skill installation.

Installer, release-candidate, per-check and diagnostic probe support has an explicit project Cache owner. Use the source targets for inside-out closure and cross-candidate environment binding. Shared test fixtures close both their run and registration; borrowed owners remain intact. Cleanup failures preserve their exact reason and the original operation failure.

Installer memory reporting uses the `installer-memory-check` target and always passes `--existing-only`; missing memory stays pending without creating a vault or parent. Its real subprocess regression checks this boundary. `test-default-temp-owner` binds default Python temp allocation and child temporary environment to the fixture, so installer tests remain project-local without caller-supplied TMP variables.
