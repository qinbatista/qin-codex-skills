# Execution and resources

[Task Analyze](../../../../task-analyze-skill/SKILL.md) owns the opening preview: intended result, qualitative difficulty, actual known models, branch roles and real dependencies. Never invent a model name. Keep chat names concise. Carry action requests through useful authorized recovery and lead with delivered changes. Keep an internal record of actual Skill names, actions and purposes across branches; give one final Skill summary, including partial/failed/paused outcomes, without repeating inventories at each stage.

[Workflow](../../../../workflow-skill/SKILL.md) owns coordination. Start ready independent work promptly, serialize real prerequisites/shared mutable owners, and prepare downstream work during external waits. Bound stale-client checks and retain exact recovery state. A confirmed submission completes that step without claiming backend completion. Close unused owned tabs; preserve active/shared/user-opened resources. Ask only for materially missing decisions or required authorization.

Before any file write, apply the [project Cache artifact policy](../../../../workflow-skill/references/project-cache-artifact-policy.md) and classify source, final-deliverable, runtime/resource or task-support ownership. For task support, allocate a fresh project `Cache/temp-<task-key>-<run-id>/` for every request or test/build/package/deploy unit, including continuation. Dependent tools and delegates share the exact run. Copy only useful continuation inputs, verify bytes/references, then release the old disposable run when its real consumers finish. A running chat does not retain completed sibling runs. Never fall back to root output folders, system Temp, Desktop, Downloads or Codex storage. Maintained source, final deliverables and actual runtime/asset Cache owners keep their boundaries.

Use [portable quiet execution](../../../../code-skill/references/skill-platform-compatibility.md): prefer Python, discovered native paths, hidden Windows subprocesses and native headless modes; capture failures, timeout and cancellation. Open surfaces only when requested. Never click approvals or restart another task. Prefer the built-in browser for browser tests and report its unavailability instead of silently switching. Apply Workflow's readable-UI rules when the actual presentation task requires them.

Follow [resource lifecycle](../../../../workflow-skill/references/task-resource-lifecycle.md) at start, transition and finish. Release each unit's exact disposable files, intermediates, handles and empty roots after verified delivery. For worktrees, verify clean state/no consumers, use Git-native removal or the Codex managed owner, and delete only eligible task-created `codex/*` branches. Never force removal or remove unrelated worktrees.

Migrate misplaced scratch only with exact ownership/identity, consumer and byte verification; moving or renaming cannot bypass a rejected deletion or establish a durable owner. Preserve active, shared, unrelated, review/reuse and retained resources until their owners and references are verified. On pause/failure retain minimum recovery inputs and clean independent disposable work. Bounds-check targets with the portable helpers; do not traverse links or purge Codex storage.
